# Кадры для слайдеров

Одна папка = одна карточка кейса на главной. Складывай сюда картинки —
я подключу их в `index.html`.

| Папка | Карточка на сайте |
| --- | --- |
| `app/` | Direct app — 4 кадра, собраны |
| `rental/` | Rental app for tenants — 1 кадр, собран |
| `doubleb/` | Loyalty program for DoubleB — 1 кадр, собран |
| `loyalty/` | Loyalty program at Direct — 4 кадра, собраны |
| `overdraft/` | Overdraft |
| `simple-campaign/` | Simple campaign at Direct — 1 кадр, видео, собран; остальные не выгружены |
| `yandex-business/` | Yandex Business |

## Как называть файлы

Порядок кадров в слайдере = порядок имён файлов:

```
01.png
02.png
03.png
```

## Что важно

- **Пропорции** — 1344 × 750, как в макете. Кадры другой пропорции обрежутся
  по центру.
- **Формат** — PNG (или JPG для фото). Ширина от 2688 px, чтобы не мылило на
  ретине.
- **Один кадр в папке** — карточка останется статичной, без точек. Два и
  больше — слайдер включится сам, точки построятся по количеству кадров.
- Тёмные кадры (как Yandex Business) — карточке нужен класс
  `slider--on-dark`, чтобы точки были светлыми. Скажи, если добавишь такие.

## Кадры-вырезки

Кадры лояльности — не скриншоты стейджа, а PNG с прозрачным фоном в 2x:
каждый занимает одну сторону стейджа целиком (два десктопных — ширину,
два телефонных — высоту) и обрезается его рамкой. Подложку даёт сам
стейдж через `--color-stage-loyalty`, поэтому такие кадры ставятся с
`object-fit: contain`, а не `cover`. Порядок задан номером в имени.

## Видео вместо кадра

Кадр может быть видео. Требования: MP4 (H.264), без звуковой дорожки или
заведомо немой, та же пропорция, что у остальных кадров папки. В разметке —
`muted loop playsinline preload="metadata"`, запуск берёт на себя
`slider.js`: видео играет, только пока этот кадр на сцене и карточка на
экране. Имя с номером, как у картинок: `01-flow.mp4`.

## Кадр больше сцены

Кадры карточки Direct app не растягиваются на сцену — каждый ставится по
своим координатам из макета (Section 5), потому что все они больше сцены
и обрезаются ею.

| Кадр | В макете | На сцене |
| --- | --- | --- |
| `01-app.png` | мокап 1455 × 1091 в (−111, −180) | там же, вровень правый край |
| `02-screens.png` | группа 1180 × 958 в (83, −104) | 1200 × 750 в (73, 0) |
| `03-recommendations.png` | группа 684 × 841 в (330, 76) | 704 × 684 в (320, 66) |
| `04-top-up.png` | фрейм 684 × 841 в (330, 76) | 704 × 684 в (320, 66) |

Числа в последнем столбце не совпадают с макетом не случайно: **экспорт
вырезки несёт по 10 пикселей поля вокруг себя**, кроме тех краёв, по
которым слайд её уже обрезал. Поэтому кадр ставится на координату из
макета минус 10, а по обрезанному краю — минус ничего. Проверить легко:
пропорция файла должна в точности сойтись с пропорцией получившегося
прямоугольника.

В CSS у таких кадров задана только ширина — высоту берёт сама картинка из
своей пропорции. Второе число тут легко разъезжается с первым, и кадр
перекосит.

## Исходники

`_original/` — то, что не идёт на сайт: полные записи до обрезки, старые
версии кадров. Эта папка не подключена нигде, лежит для отката.
